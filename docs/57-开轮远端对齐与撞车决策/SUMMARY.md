# SUMMARY · round 57 —— 开轮远端对齐与撞车决策

## 一、开发项背景

两条 issue 出自 round 55 的**同一次撞车**，覆盖它的前后两半：

- **[#114](https://github.com/pkulijing/claude-code-global/issues/114)**（`type:feat` / `area:skill` / **P1**）—— 撞车**发生前**：`/start` 完全不碰远端，撞车只能等到 `/finish` 之后才暴露。
- **[#116](https://github.com/pkulijing/claude-code-global/issues/116)**（`type:docs` / `area:doc` / P2）—— 撞车**已经发生**：宪法没有对应的决策路径，只能靠人当场拍板。

round 55 完整做完一版实现（宪法 + skill 改动、docs 四件套、**2 轮独立 context review 并 clean**、2 个 commit 落地），收尾后才 `git fetch`，发现**远端 6 天前就修完了同一个 issue（#91）且更全面**。整版作废，最终 diff 只剩 3 行。代价是一整轮的开发 + 两轮 review 的 token + 人的注意力。

本仓正是「多台机器 + 云端 routine 都在写」的场景，这类撞车**必然反复出现**。

## 二、实现方案

三个 commit，一条主线：**让「远端已经做过了」在开轮那一刻就可见**。

| commit | 内容 |
| --- | --- |
| `aa20f8c` | `platform_issue.py` 的 `issue-view` / `issue-list` 吐出归一的 `state` / `stateReason` |
| `ac91329` | `/start` 新增「远端对齐」为通用流程第 1 步；轮次编号三源 → 五源（**Closes #114**） |
| `488b4cd` | 宪法补「交付物与远端已合入实现撞车」的停机子类（**Closes #116**） |

### 2.1 先实证，推翻了 issue 正文里的一条命令

按 `/start`「外部行为断言先实证」，动笔前把 #114 正文里的 git 断言跑了一遍真沙盘，**推翻一条**：

issue 给的 `git log origin/master --grep "Closes #<N>"` **有 bug** —— `--grep` 是正则子串匹配，**查 `#11` 会命中 `Closes #114`**。照抄进 skill 就是「开轮被一条毫无关系的 issue 拦住」，且越是小号 issue 越容易撞。

这条实证决定了后面所有的边界设计，也是本轮「照抄需求会怎样」的活样本。

### 2.2 三个撞车信号，各补各的盲区

| 信号 | 命令 | 补的盲区 |
| --- | --- | --- |
| issue 自身 `state` | `platform_issue.py issue-view <N>` | **不依赖提交信息约定** —— `/start` 是全局 skill，别的项目未必写 `Closes #N`；还能覆盖 `wontfix` 关闭（**有人决定不做**，与「做完了」处理方向相反） |
| 已合入的关闭 commit | `git log origin/<主分支> --grep ...` | 给人类拍板要看的**证据**：谁做的、哪个 commit、什么时候 |
| **远端在途分支** | `git log --remotes=origin --not origin/<主分支> --grep ...` | 「分支上已做完、PR 还开着、issue 还 open」—— 本仓 `/routine-dev` 每周开 PR 却不自动合，正是这个形态，前两个信号都看不见它 |

第三个信号是 issue 原文没想到的，本轮补的。

### 2.3 关闭动词正则：两侧边界都要，且不能用 `[a-z]*` 一把抓

最终形态：

```
(^|[^a-z])(close[sd]?|fix(es|ed)?|resolve[sd]?) #<N>([^0-9]|$)
```

- **右边界** `([^0-9]|$)` 挡「查 `#11` 命中 `#114`」；
- **左边界** `(^|[^a-z])` + **按 GitHub 真实关键字清单枚举**的动词，挡语义相反的句子。

第二条是 review 抓出来的：我先写成 `(clos|fix|resolv)[a-z]*`，于是 `still unresolved #11`、`not fixing #11` **都会命中** —— 把「还没修」报成「已经修完了」。**补左边界还不够**（`fix[a-z]*` 照样吃掉 `fixing`），根因是 `[a-z]*` 太宽。GitHub 认的关闭关键字只有 close/closes/closed、fix/fixes/fixed、resolve/resolves/resolved，**没有进行时**。

### 2.4 `state` 归一：赌注押在两端词形一致的那一侧

GitHub 是 `CLOSED`、GitLab 是 `closed`，小写后同字；而「打开」两端词形不同（`OPEN` vs `opened`）。**判据挂在 `closed` 上**，本机没装 `glab` 无法实测的那一端才不会判错。失败方向同样定死：**判不出一律算 `open`** —— 照常开轮，而不是把人拦在门外。

### 2.5 降级：三条独立失败路径，一条都不阻断开轮

无 `origin` remote / `fetch` 失败 / `issue-view` 拉不到，全部只提示不阻断。`state` 走平台 API、commit grep 走 git，**两条路互相独立**，一个挂了另一个照跑。

### 2.6 宪法：分类轴不能只有「谁更全面」

三行取舍表（远端更全 → 弃己方；各有独有 → 重写增量、别硬 rebase；己方更全 → 保留并说明吸收了什么）之外，review 逼出了一条关键补充：

只按覆盖面比，**「远端更全但有 bug」会被归进第一行**，于是拿一个有缺陷的实现换掉自己已经验过的版本。故补前置：**「更全面」不等于「更对」**，弃己方之前先核实远端真的能用；判不准或落表外则走最保守那行。

备份 tag 写出**完整命令**（`git tag backup/<分支名>-$(date +%Y%m%d-%H%M)`，与 `/rebase` / `/finish` 逐字一致）而非只说「打个 tag」—— 这条规则可能在不经那两条流程时触发，不写就各轮发散，而它的全部价值就在事后翻得到。

### 2.7 额外产物

- `scripts/platform_issue.md` 新增「issue-view 语义」一节（schema 真源）；
- `skills/triage/SKILL.md` schema 枚举同步；
- 测试**并进脚本自带的 `--self-test`**（详见 §3.2）。

## 三、局限性

### 3.1 修复的有效性本轮无法自证

`/start` 的远端对齐要等**下一轮真开轮**才知道是否被执行。本轮开轮时我手动跑了全套（fetch + 三信号 + 五源编号），算一次预演，但预演的人知道自己在测什么 —— 与 round 55 §3.1 是同一个问题。

**观察点**：下一轮 `/start` 的输出里有没有远端对齐那几行。

### 3.2 测试落点中途改了，PLAN 与实现不一致（已在 PLAN 留痕）

原计划新建 `docs/57-*/test_platform_issue.py`（19 例 unittest，先红后绿，确实这么做了）。review 查出脚本**自带一套 `cmd_self_test()`**，硬编码着旧 schema 期望值，改了 schema 没同步 → `--self-test` 直接红（exit 1、7 条 FAIL）。

更要紧的是**它才是被文档承认的门禁**（`skills/routine-dev/SKILL.md:186`）。留两套测试 = 新增的 state 逻辑不在门禁覆盖内，将来门禁绿着而归一已经坏了。故并进 `--self-test`、删独立文件。**代价**：失去 `unittest` 的命名用例与 `subTest`，换成 `failures.append` 惯例。

### 3.3 GitLab 端未实测

本机没装 `glab`。`state` 归一按「只赌 `closed` 一个词」设计以降低风险，但 GitLab 端的实际 JSON 字段**从未跑过**。

### 3.4 「核实远端实现真的能用」没有可操作标准

宪法新条要求弃己方前先核实远端能用，但没给最低标准（跑测试？读代码？）。reviewer 判 <80 未上报，理由是与本文件其它判断性条款（「实测结论」「代价高于重写」）留白程度相当。**仍是一个已知的软处**。

### 3.5 `skills/start/SKILL.md` 增了 3,023 字符，是 PLAN 估值的 2.5 倍

PLAN §4.4 估「约 +1,200 字符」，实际 +3,023（该文件 5,381 → 8,404，**+56%**）。懒加载不进常驻面，但**估算方法本身不可靠**这件事值得记。宪法 +663 字符（常驻面 +4.3%），总指令面 +2.0%。

### 3.6 我误判了 `review-orchestrator`，并据此绕过了它一次

**先说结论：orchestrator 没坏，是我的任务书没写清收尾条件。**

实际记录：本轮共调它 5 次。**4 次正常返回完整 finding**（单元 1 两轮、单元 2 第 1 轮、以及事后补做的对照实验），其中那条 85 分的「顺延步号漏了正文引用」和 78 分的「关闭动词正则缺左边界」都是它给的。只有单元 2 第 2 轮那次返回「还在等角度 ②」，催一次仍是「还在等」，第二次明确要求「别等了、自己补审」后**它完整跑完并给出了 78 分那条**。

我当时把这归因为「orchestrator 收不回子 agent 结果 / 不可用」，并在单元 3 直接绕过它、改用主会话委派 3 个单角度 reviewer + 自己汇总。**这个判断下重了**：一次卡住不等于不可用，而我没做任何对照就换了装配方式 —— 恰恰违反了宪法「『能力不可用』以实际调用失败为准，不以推断为准」的精神（我有一次真实失败，但把它外推成了通例）。

**事后做了对照实验**：拿单元 3 完全相同的那份 diff（`488b4cd` 的 `GLOBAL_AGENTS.md` 改动）交给 orchestrator 重跑，任务书里补上一句它此前缺的收尾要求 ——

> 必须在最终回复里给出完整结论；某个 reviewer 迟迟不返回就自己按 `angles.md` 原文顺序补审那个角度，**不要**只回一句「还在等」。

结果：**3 个 reviewer 全部返回、结论 clean**，与我直接委派得到的结论一致，还多出一条 55 分的观察（「先盘点…再按下表取舍并请人类确认」的动作顺序略模糊）。

**真正的教训是任务书的**：`/review-loop` 的 orchestrator 任务书六条里没有「拿不到子 agent 结果时怎么收尾」这一条。缺了它，orchestrator 空手返回一句「还在等」是合规的 —— 它既没报错也没降级，**主会话若不追问就等于 review 白跑而无人知**。这才是值得沉淀的点，不是「orchestrator 坏了」。

**遗留**：单元 3 的 review 事实上是主会话汇总的（三个角度的原始结论完整保留在 `REVIEW.md`），对照实验已用 orchestrator 复核过同一份 diff，结论一致。

### 3.7 撞车检查只覆盖 issue 驱动分支

自由描述分支不做（刻意：没有 issue 号就没有可查的信号）。`/quick` 也吃 issue 号但同样不做（PLAN §八 明确排除，轻量流不背这套检查）。

### 3.8 只查提交信息，squash merge + PR 标题没写关键字会漏

三个信号里有两个依赖提交信息含关闭关键字。远端若用 squash merge 且 PR 标题 / body 都没写 `Closes #N`，这两个信号会落空 —— 此时只剩 `state` 兜底（它够用，但证据那一半就没有了）。

### 3.9 本轮被自己要解决的那类问题命中了，且是自己的修复覆盖不到的变体

收尾时发现**同时存在第二个 round 56**（`round56-routine分诊结果缓存`），它在本轮进行期间开轮、并**先一步合入 master**。故本轮顺延为 **57**：docs 目录改名、四份文档的内部引用、DEVTREE 三处（索引行 / Epic 轮次 / mermaid 节点）、以及四个 commit 的 `[round N]` 前缀全部改过。

**为什么本轮的修复拦不住它**，值得说清楚 —— 三个撞车信号与五源编号全都失效在同一个点上：**开轮那一刻，那个分支还不存在**。

| 防线 | 为什么没拦住 |
| --- | --- |
| issue `state` | 两轮做的是不同 issue，各自都 open，天然无交集 |
| 已合入的关闭 commit | 开轮时它一个 commit 都还没有 |
| 远端在途分支 | 它是**本地**分支，从未 push |
| 编号源②（本地 `round*` 分支） | 开轮时它还没被创建 |

即：本轮防的是「**开轮前**已经存在的撞车」，而这次是「**开轮后**才出现的并发撞车」。二者需要的机制不同 —— 前者靠开轮时查一次，后者只能靠**收尾时再查一次**（或某种编号预占）。

`/finish` Step 4.5 的编号一致性检查确实把它逮住了，但那是**人工核对触发的**，且它检查的是「本轮 rebase 后编号是否脱节」，并未把「另一轮抢先占了同号」当作显式判据。

**这条正好补上了 #114 的射程边界**：`/start` 的远端对齐降低了撞车概率，但**消不掉并发窗口**。见「可沉淀项」第 4 条。

### 3.10 顺延带来的两处历史痕迹

- 四个 commit 的 `[round 56]` 前缀经 `filter-branch` 改写为 `[round 57]`（本轮分支未 push 过，改写不影响他人）；
- docs 目录在 commit 1–3 里叫 `docs/56-*`、在收尾 commit 才改名为 `docs/57-*`（无交互式 rebase 可用，未把改名摊进每个 commit）。最终树是对的，但翻单个中间 commit 会看到旧编号。
