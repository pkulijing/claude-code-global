## 二、改动 1 · 宪法「提交前 review」节加正面授权声明

**插入位置**：现有「**降级不跳过，且降级有门槛**」段**之前**。理由：授权是前提，门槛是它的推论 —— 先声明授权，再说明什么情况下才允许降级，逻辑顺序自然。

**与远端已有表述的分工**（避免双写）：

| | 远端已有（门槛段） | 本轮新增（授权段） |
| --- | --- | --- |
| 语气 | 防御式：「……不构成降级理由」 | 正面式：「长期授权，无需逐次征询」 |
| 作用域 | 绑定在 review 降级判断上 | 任何需要委派的场景 |
| 论证 | 详述「为什么条件已满足」 | **不重复论证**，只声明授权、并指出它是门槛段那句「条件已满足」的依据 |

**措辞边界（本轮最需谨慎处，写错就是开后门）**：

- 写成「某类条件式指令的条件**已被满足**」——**如实陈述**（指令原文就是条件式，用户调 skill 确实满足了它）。
- **绝不**写成「忽略平台指令」——那是**通用后门**，将来任何平台指令都能援引。
- 故声明必须**自带作用域限定**：仅覆盖「委派子 agent」这一件事。

拟增文本（约 3 行）：

> **子 agent 委派已获长期授权（不限于 review）**：用户在本文档中**长期授权** Coding Agent 在本工作流内自主委派子 agent —— review 编队、skill 内部并行子任务等，**无需逐次征询**。这条授权正是下文降级门槛里「条件已满足」的依据，且**作用域更广**：它覆盖任何需要委派的场景，不只是 review 前的降级判断。**但严格限于「委派子 agent」这一件事，不推广到任何其他平台指令。**
