# SUMMARY · round 55 —— 委派授权声明

## 一、开发项背景

### 1.1 表现

用户反馈：

> 还是 review 的问题，我们搞了 agent 后，并没有收到预期的效果，你频繁给我发这条消息：「本轮未经独立 context 的 review。本会话禁用子 agent 委派，按宪法降级链退到本端结构化自审并在此标注。」我并没有禁用子 agent，到底是谁在禁用？**如果需要的话，在宪法里明确允许子 agent 的委派。**

即 `/review-loop` 的独立 context 保证形同虚设：编队机制建成了，但实际反复退到「本端结构化自审」，且降级理由是模型臆想的。

### 1.2 根因（排查结论）

**平台侧：一条用户不可见也不可关的常驻系统提示。** CC 二进制里硬编码 `Do not call the AgentTool unless the user requested it`，服务端 flag 控文本、另有 kill switch，仅对 `opus_5_prompt_bundle` 档模型（Opus 5 / 4.8 / Fable 5）注入；不来自任何一层用户配置（逐一核查过），sonnet 会话不复现故极易被误判为偶发。实测 CC 2.1.222 仍在。**具体常量名 / flag 名留在 `PROMPT.md` 档案，刻意不进指令面**（见 §2.3）。

**模型侧（能修的那层）：** ① 把 "unless **the user requested it**" 这个**条件式策略约束**读成**能力缺失**；② **一次都没试过**就静默降级，还留下看似合理实则错误的理由 —— 人极难据此察觉门禁已失效。

### 1.3 本轮的真实形状：撞车后重做

排查完、并在同一会话内实测委派可用之后，本轮**最初完成了一个完整实现**（宪法两段 + `review-loop` Step 5 拆 5.1/5.2 + 对照表 + 事故引述块，含 2 轮独立 review、clean 收敛、docs 四件套齐备）。

随后 `git fetch` 发现：**#91 已由远端 `735c04c`（8/2）修复并合入**，且远端版本**比最初版更全面** —— 多出「无人值守例外」（云端 routine 没有「停机问人」这个选项，挂起等于整次运行报废）与 `/commit` 第 7 步的写入联动，二者都是最初版的遗漏。

同时撞上两处冲突：**轮次撞车**（远端已有 `docs/53-review成本与思考深度调优/` 与 `docs/54-routine手动标记扩面/`）、**同段落冲突**（远端 round 53 重构了 `review-loop`，新增 `agents/` 编队定义与 `references/angles.md`）。

经人类拍板：**弃掉最初版，只在远端最新基础上补真增量。** 弃用版本保留在备份 tag `backup/round53-弃用-20260808-1221`（含 `5d63c23` / `e21e10e` 两个 commit）。

**因此本轮的头号风险不是漏改，而是与远端已有表述重复** —— 双写必然漂移。

## 二、实现方案

最终 diff **仅 3 行**，指令面 +0.2%。

### 2.1 宪法：一条正面的委派授权声明

远端 `735c04c` 的表述在**降级门槛**语境里（「……不构成降级理由」），是**防御式**的：告诉模型「考虑降级时别拿那条平台指令当借口」。

缺的是**正面授权**，也正是用户这次点名要的那条：

> **子 agent 委派已获长期授权（不限于 review）**：用户在本文档中**长期授权** Coding Agent 在本工作流内自主委派子 agent —— review 编队、skill 内部并行子任务等，**无需逐次征询**。这条授权正是下文降级门槛里「条件已满足」的依据，且**作用域更广**：它覆盖任何需要委派的场景，不只是 review 前的降级判断。**但严格限于「委派子 agent」这一件事，不推广到任何其他平台指令。**

放在「降级不跳过，且降级有门槛」段**之前** —— 授权是前提，门槛是推论。

**与远端的分工**（刻意不重复）：新增段只回答「授权从哪来、作用域多广」；既有段只回答「什么算失败、核验门槛是什么」。经 3 reviewer 独立核验判定为「前提 → 推论」的互补关系。

### 2.2 措辞边界 —— 本轮最需谨慎处

授权**必须**写成「那类条件式平台指令的条件**已被满足**」；**绝不能**写成「忽略平台注入的指令」。

- 前者是**如实陈述**：指令原文就是条件式，用户调用 skill 确实满足了它。模型此前是**读错了**，纠正读错是正当的。
- 后者是**通用后门**：将来任何一条平台指令都能援引，等于在宪法里写「平台说什么都不算数」。

故声明**自带作用域限定句**。该边界经 3 reviewer 专项核验，一致确认误读路径已封堵。

### 2.3 刻意不把上游内部实现写进指令面

`Kep` 常量、`tengu_heron_brook` / `tengu_fennel_godwit` flag、`opus_5_prompt_bundle` capability、CC 版本号 —— 这些**只留在 `PROMPT.md` 档案里**。

依据是本仓 round 50 已确立的做法（「对上游内部实现的逆向描述全删」）：这类描述随版本漂移、且读者无法验证。留在档案里的价值是**将来服务端换文本时能快速比对**，这不需要它们常驻指令面。

### 2.4 `review-loop`：堵住「伪造降级证据」

远端已要求「留痕必须带证据」，但留了反向逃逸口：**既然有证据要求，就可能构造一次没发生过的调用来满足它**。句尾追加半句：

> **写不出证据，本身就说明不该降级** —— 此时的正解是回去把委派做完，**绝不是编一次没发生过的调用来填这一栏**。

与既有的「必须实际核验过」针对**不同失败模式**：后者防「凭推断说不可用」，前者防「编造证据」。

## 三、局限性

### 3.1 修复的有效性无法在本轮证明

本轮的成功委派**不构成充分证据** —— 对话里明确讨论过这个问题、用户明确要求委派生效，这本身就是极强的上下文信号。真正的考验是**一个没讨论过此事的全新会话**。

观察点：后续轮次的 commit message / REVIEW.md 里是否还出现「禁用 Agent 工具」这类降级标注。

### 3.2 同模型自审盲区，本轮尤其突出

改的正是「防止模型误判」的规则，而 review 也由同家族模型执行 —— **判断措辞会不会被读歪的，正是可能读歪它的那个模型**。缓解手段（作用域限定句、专项攻击式 prompt）只降低概率，不消除。

### 3.3 编队档位未由 frontmatter 钉死（本轮实际降级点）

`agents/review-orchestrator` 类型在委派时点不在会话可选类型里（实测报错见 `REVIEW.md`），故改用 `general-purpose` + 显式 `model` 委派。**独立 context 保住了，未退到本端自审**，但 `agents/*.md` 作为「编队档位单一真源」的机制**本轮未经实测**。

### 3.4 `agents/` 此前根本没软链过去

本轮发现 `~/.claude/agents/` **不存在** —— 远端新增该目录后本机未重跑 `install.sh`。这意味着在此之前，`review-loop` 指定的 `review-orchestrator` 编队在本机**一直不可用**。已在本轮补跑 `install.sh` 修复。

**这暴露了一个更一般的问题**：`install.sh` 是否重跑靠人记，而 `auto-update.sh` 虽每小时跑一次，本机却滞后到本轮才被发现。滞后窗口内 skill 指向的能力可能整个不可用，且无任何告警。

### 3.5 弃用版本里有未被吸收的内容

被弃的 `e21e10e` 含若干本轮未保留的东西：算失败 / 不算失败**对照表**（表格比散文更难读漏）、round 51 事故引述块、「唯一例外是工具压根不存在」的显式排除条款。远端版本以散文穷举覆盖了同等信息，故未强行搬运，但**表达形式的差异是否影响命中率，无实证**。

### 3.6 本轮未验证跨端影响

`GLOBAL_AGENTS.md` 双端共读（CC + Codex）。新增的授权声明在 Codex 端读起来是否合适（Codex 无 Agent 工具、必然走降级）**未实测**，仅做文本层面判断。

1. **多设备并行开发撞车的检测应当前移。** 本轮完整做完一版、跑完 2 轮 review、commit 之后才 `git fetch` 发现远端早已修完同一个 issue，整版作废。**`/start` 在开轮前就该 fetch 并检查目标 issue 是否已被远端 commit 关闭**（`git log origin/master --grep "Closes #N"`），代价是一次 fetch，收益是避免整轮返工。这条价值最高。
2. **「弃掉自己刚做完的工作」需要一条明确的决策路径。** 本轮靠人类拍板。判据可以固化：远端已实现同一需求且更全面 → 弃己方、只补增量；两边各有独有价值 → 取增量合并；己方更全面 → 保留己方并说明。属于宪法「计划假设被证伪时的停机义务」的一个具体子类。
3. **`install.sh` 未重跑导致 skill 指向的能力静默不可用**（§3.4）。值得一个通用机制：skill 依赖的外部资源（agent 定义、脚本、模板）缺失时应当**显式报错并给出修复命令**，而不是让模型自行找替代路径 —— 后者正是「静默降级」的温床。
