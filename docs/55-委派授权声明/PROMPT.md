## 二、谁在禁用（排查结论，本轮不再重复调查）

**Claude Code 自己，用户不可关。**

模型的系统提示里被注入两行：

```
Do not call the AgentTool unless the user requested it
Do not use workflows or deep-research unless the user requested it
```

- **不来自任何一层用户配置** —— `~/.claude/settings.json`、`settings.local.json`、项目级 `.claude/settings*.json` 全部无此内容（本轮逐一核查）。
- **硬编码在 CC 二进制里**（`Kep` 常量）。文本可被服务端两级覆盖（clientData 的 `tengu_heron_brook` → feature flag `tengu_heron_brook`），`tengu_fennel_godwit` 作 kill switch；注入条件是模型带 `opus_5_prompt_bundle` capability。
- **仅 Opus 5 / Opus 4.8 / Fable 5 档注入** —— sonnet 会话根本不复现，故极难复现、极易被误判为偶发。
- **实测版本 CC 2.1.222**，`strings` 仍命中。

> 上述常量名 / flag 名**只留在本档案里，不进指令面** —— 本仓 round 50 已确立「对上游内部实现的逆向描述全删」的做法（那类描述随版本漂移、且无法验证）。这里保留是为了将来服务端换文本时能快速比对。

**模型侧的两层误判**（这才是能修的那层）：① 把 "unless **the user requested it**" 这个**条件式策略约束**读成**能力缺失**；② **从未实际尝试过**就静默降级。

## 四、本轮要做的（两条真增量）

### 4.1 宪法：一条**正面的、独立的**委派授权声明

远端现有表述在**降级门槛**语境里（「……不构成降级理由」），是**防御式**的：它告诉模型「考虑降级时别拿那条指令当借口」。

缺的是**正面授权**：用户长期授权在本工作流内自主委派子 agent，**不限于 review 降级判断这一个场景**（还包括 skill 内部并行子任务等任何需要委派的地方）。

用户这次的原话就是「在宪法里明确允许子 agent 的委派」—— 要的是这一条。

**措辞边界（本轮最需谨慎处）**：

- 必须写成「某类条件式平台指令的条件，在本工作流下**已被满足**」—— 这是**如实陈述**，指令原文就是条件式，用户调用 skill 确实满足了它。
- **绝不能**写成「忽略平台注入的指令」—— 那是**通用后门**，将来任何一条平台指令都能援引。
- 故声明**限定作用域**：仅覆盖「委派子 agent」，不推广到任何其他平台指令。

### 4.2 `review-loop`：堵上「伪造一次调用来凑证据」

远端已要求「留痕必须带证据」，但没堵住反向逃逸：既然有证据要求，模型可能**构造一次不存在的调用记录**来满足它。一句话补上。

## 五、明确不做

- **不重复远端已有的门槛判据**（会造成双写漂移）。
- **不试图关闭那条平台指令**（服务端 flag 控制，客户端无从关闭，也不该 hack 二进制）。
- **不把常量名 / flag 名写进指令面**（见 §2 注）。
- **不碰** `agents/`、`.github/`、`install.sh`、`scripts/`、`hooks/`、`templates/`、两条 routine 的 SKILL.md。
- **不新开 issue**（#91 已关，本轮是其增量）。
