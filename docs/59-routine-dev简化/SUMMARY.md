# SUMMARY —— round 59 · `/routine-dev` 简化

## 开发项背景

上一轮讨论中人类对 claude.ai Routines 下了结论性判断：**云端没有 uv、没有自定义镜像、没法指定 Python 版本，这是 routine 机制的失败，长期不该依赖它做复杂的事。**（已沉淀为 memory `cloud_routine_complexity_ceiling`。）

`/routine-dev` 是这条判断下最该被审视的对象：它的 `SKILL.md` 达 19,356 字符，是整个指令面**最大的单文件**，比宪法 `GLOBAL_AGENTS.md`（11,107）还大一截。开工前按节实测了它的构成，结论是**占大头的不是安全边界**：

| 类别 | 占用 |
| --- | --- |
| 安全边界（四条红线 / 不触发合入 / 不发评论 / 落点白名单） | ~3.5 KB，全是短禁令 |
| 多 issue / 多 PR 的编排（合批不变式 + 落点并集复核 + 在途 PR 照料） | ~11 KB |
| `auto:skip` 缓存层 | 5.1 KB + 一个事件驱动 workflow |
| 双端分岔 + 无人值守契约 | ~4 KB |

即：**贵的是「一次跑多条、出多个 PR、还要管在途 PR」的衍生债，以及一层为省分诊 token 引入的缓存。**

## 实现方案

### 三刀

**刀 A · 删掉整套 `auto:skip` 分诊缓存。** 删 SKILL §1.3、`.github/workflows/auto-skip-reset.yml`（整文件）、`labels.yml` 条目、`security-boundary.md` 的「辨析：给 issue 打 auto:skip」一节，以及 README / 本仓 `CLAUDE.md` / `/triage` / `scripts/platform_issue.{py,md}` 的连带引用。它换来的只是每周三次少读几条正文的 token，代价却是快照 / 时间戳复核 / fail-closed / 残余窗口 /「改判据要清全仓标」这一串跨机制耦合。**远端 label 由人手动 `gh label delete` 删除**（helper 无 `label-delete`，`label-sync-from-file` 只 create/update）。

**刀 B · 删掉 Step 0.5「照料在途 PR」**（rebase 解冲突 + force-push），连带 `security-boundary.md` 原 §3/§4/§5（三节全为它而写）。冲突让 `ff-merge` 失败、显式暴露给人，回本机处理。

**刀 C · 退回「一次运行只出一个 PR」。** 删合批整节与 `--max-prs`，落点复核从 2.4 KB 的并集簿记塌缩成两条直线检查，cherry-pick 到已开 PR 的路径取消，连带删原 §6。**这一刀的依据就写在被删的 §6 里**：那套机制在本仓的实测结果本来就是「一次运行通常只出 1 个 PR」（几乎每批都要动 `README.md` 或 `GLOBAL_AGENTS.md` 那两张登记表，于是全并成一批）。实际吞吐就是 1，不必为「理论上是 N」养一整套编排。

### 连带收益：写权限面收紧为穷举三样

| | 前 | 后 |
| --- | --- | --- |
| label | 给 issue 打 `auto:skip` | **不打任何 label** |
| push | 新分支 + **force-push 已有 PR 分支** | **只 push 新分支** |
| PR | 开 PR、编辑描述 | 不变 |

原先「绝不给 **PR** 打 label」需要配一整节辨析证明「给 issue 打是安全的」；现在 routine 压根不需要写 label，**能力不存在比「有能力但按规则不用」强一档**，直接收到零，那节辨析随之不必要 —— 这正是刀 A 能连带删掉 1.5 KB 推导的原因。

### 一次一条必须补的两块（唯一的加法）

- **1.3 选取规则**：标记通道优先 → `priority` 升序 → issue 号最小；**分诊短路**（按序读正文，第一条合格即停）。这把刀 A 省掉的 token 又赚了回来，而且是靠「不去读」而非「记住上次读过」。
- **撞车检查**：分诊时按预期落点排除撞在途 PR 的 issue，开 PR 前用真实 diff 再核一次。

### review 逼出来的两处加固（本轮质量的主要来源）

两轮重档 review（`review-orchestrator` + 4 × `code-reviewer` + 1 × `code-reviewer-deep`，走第 ① 档未降级）报了 3 条过 80 分线，全部已修。**其中前两条是真正有价值的**：

1. **确定性活锁**（88）：1.3 排序是纯函数、短路只读到中标那条，而我把开发期所有分岔都写成「放弃本次运行」，刀 A 又恰好拿掉了唯一的跨运行记忆 → 队首一条确定性失败会每周三次原地复现，后面的 issue 永久饿死，零 PR 意味着无人知晓。**两刀单独看都没问题，叠起来才有。** 改为「换下一条候选、最多试 3 条」。
2. **登记文件通则被删漏**（80）：「共享登记文件也算落点」原先寄生在合批节里，是撞车预判**真正的判据**，跟着刀 C 一起没了 → 预判形同虚设。补回 1.2。
3. **重试循环清理不干净**（85）：`git restore` 对已 `git add` 的是 no-op、对未跟踪新文件无效，而 `git checkout` 会把残留原样带走 → 候选 A 的文件混进候选 B 的 PR。**撞红线那条分岔尤其致命**（A 正因写到 `agents/` 才被放弃，残留却被带进 B，而开 PR 前的复核不重新判红线）。改为规范清理块：`git reset --hard` + `git clean -fd` + 切回 + 删分支 + 复检 `porcelain` 为空。

**明确否决的修法**：重新引入跨运行持久标记来解活锁 —— 它与本轮刚收紧的「绝不打任何 label」直接冲突，用安全边界换吞吐不划算。该否决连同理由写进了 SKILL 的「残余」块。

### 量化结果

| | 前 | 后 |
| --- | --- | --- |
| `skills/routine-dev/SKILL.md` | 19,356 字符 | 15,999（−17%） |
| `references/security-boundary.md` | 5,240 | 3,208（−39%） |
| `.github/workflows/auto-skip-reset.yml` | 58 行 | 删除 |
| 整个指令面 | 195,675 | 190,162（−2.8%） |

**它仍然是指令面最大的单文件**（15,999 > `playbooks/python.md` 14,750 > 宪法 11,107），只是对宪法的差距从 8,249 收窄到 4,892。别把这轮的降幅读成「routine-dev 已经不大了」—— 想挑下一个精简目标的人，答案还是它。

### 额外产物

- `security-boundary.md` 删四节后**重编号为 一/二/三**（宪法「痕迹形态」表：编号缺口本身就在暗示这里曾有过一条），SKILL 的 Step 3/4/5 同理顺移为 2/3/4，全部跨文件 §N 与 Step N 引用同步改过。
- Step 1 改为**先只拉 label 层**（`issue-list --no-body`），正文按 1.3 的顺序单条取 —— 否则「第一条合格即停」省下的只是模型判断，正文还是全拉了。
- `scripts/platform_issue.py` 的 `issue-label-add` / `issue-label-remove` / `--no-body` **保留**（通用能力、有单测），只把注释里「为 auto:skip 而生」的动机改中性、测试夹具字符串换成 `auto:take`。

## 局限性

1. **没打到验收目标。** PROMPT 定的是 SKILL.md 降到 24 KB 上下（字节口径 −35%），实际停在 31.2 KB / −18%。差额是 review 逼出来的两处加固（重试机制 + 规范清理块）及其 WHY。**不打算为了对上数字把它们压回去** —— 那段 WHY 正是防止后来者把它「简化」回一个 bug。
2. **`/review-loop` 2 轮上限用满，第 2 轮所修的规范清理块未经独立 context 复审。** 已按硬规则留痕放行，记在 `REVIEW.md`「未收敛遗留」与 commit message。
3. **活锁只是降级、没有根除。** 3 次上限内若始终是同样那几条排前面且都失败，它们后面的仍轮不到；那次零 PR 时连报告都发不出。缓解只有「只要最终出了 PR，尝试过并放弃的都写进『本次未选中』段」。彻底解要么重新引入跨运行持久标记（与「绝不打任何 label」冲突，**已否决**），要么给云端一条真正的输出回路（今天没有）。
4. **吞吐从每周 ≤5 个 PR 降到 ≤3 条 issue**（一 / 三 / 五各一条）。这是本轮目的本身，不是回归。
5. **在途 PR 冲突不再自动修**，需人回本机处理。
6. **全量分诊结论不再有出口**（短路 + 无缓存）。全量视图归本机 `/triage`。
7. **本轮全部未经真实云端运行验证** —— 改的是 routine 的剧本，下次周一 / 三 / 五那次运行才是第一次真跑。

2. **「两处改动各自安全、叠起来出洞」的组合效应** —— 刀 A（拿掉跨运行记忆）× 刀 C（放弃粒度升格）叠出永久饿死，两刀单看都干净。**去向：本仓 `/backlog`**，落点建议是 `/review-loop` 的 `references/angles.md` 加一个「同轮多处改动的交叉影响」审查角度。
3. **`head/cat/tail > tmp && mv` 重写文件会丢权限位** —— 本轮真丢过一次（`platform_issue.py` 755→644，commit 时才发现）。**去向：暂不沉淀**，属工具使用细节、够不上跨项目资产的三条判据。
