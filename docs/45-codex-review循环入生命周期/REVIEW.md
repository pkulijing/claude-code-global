# REVIEW 迭代留痕（round 45 自举）

本轮实现「commit 前自动 review loop」机制，并**用该机制自举 review 自身实现**——即用独立模型（codex）review 本轮 diff，跑真实的 review→修→复审循环。以下是各轮迭代。

## 已定设计前提清单（每轮 review 作为 focus 传给 codex）

这些是**人类明确拍板、不容独立模型再质疑**的设计决策。codex 若报「问题」实质是质疑其中某条，不算未收敛（它只是不知道已定）：

1. **review 整个工作树、不做文件集隔离**：让独立模型看到全部 diff 并可自由翻阅任意未改文件看上下文；锁死范围会让 review 变瞎。安全（凭据不外发）**靠 `.gitignore`**（`.env.local` 本就该 ignore，宪法「环境变量管理」硬性规定），不靠 skill 自己 stash/隔离。自动修复只改本次相关文件、不碰无关文件。
2. **commit 由 Agent 自主收口**：开发单元完成即主动 `/commit`、不干等用户；commit 前自动 review 迭代至 clean；人类 review 前移到 `/finish`。
3. **降级极简**：只探「codex 在不在」（假设本机 codex 装好即可用，不纠结 token/登录/CLI 缺失等复杂状态）；不在→停下告知用户后降级本会话自审。
4. **不区分 staged/untracked**：`/commit` 前工作树没有谁提前分批 `git add`，review 整树一把梭即可，不区分不合并。
5. **落点 = 新 skill + 宪法约定**，不做 hook。

## 关键转折：人类推翻「范围隔离」整条错误路线

第 8～11 轮 codex 反复在「review 范围隔离」这条线上挖（stash untracked、stash tracked、`--scope staged`、description 同步…），我一层层打补丁、越补越复杂。**人类一句话点破前提本身是错的**：

- review 代码本就该看 **diff**、并让 reviewer **自由翻阅任意文件看上下文**——一处改动的正确性常依赖它调用/被调用的**未改动**文件；锁死「只审本次提交文件集」反而让 review 变瞎。
- 安全（不泄露凭据）的正解是 **`.gitignore`**（`.env.local` 本就该 ignore，见宪法「环境变量管理」），review 天然不碰被 ignore 的——**根本不需要 skill 自己 stash/隔离**。

**纠正**：删掉 Step 1 的「文件集隔离」与 Step 4 的 stage/stash/pop 整套机制，回归 `/codex:review --wait --scope working-tree`（审整个工作树、codex 自己找上下文）。第 8～11 轮那些「范围隔离」补丁是在**错误前提**上反复精化，一并作废——skill 大幅简化。

**教训**：独立模型 review 很强，但**它也可能在一个错误前提上帮你越修越精致**——人类的价值在于质疑「这件事本身该不该做」，而非只在既定框架内找 bug。这是本轮比「codex 逐层抓 bug」更深的一条元经验。

## 第 12 轮：codex 复审（验证简化版）

codex **仍报 P1 坚持要「文件集隔离」**——但这正是人类已推翻的前提，codex 不知情故反复提。**判定：不采纳其方案**（隔离），**吸收其有效内核**（自动修复别碰无关文件 → 加入 Step 6 修复纪律）。这暴露独立模型的一个局限：**它会在一个错误前提上锲而不舍地帮你「修」**。→ 催生下面的「传已定前提」机制。

## 关键机制升级：给 codex 传「已定前提」focus

人类提议：codex review 能不能**传入提示**，把已明确的结论告诉它、让它在此前提下 review？查证 companion：native `/codex:review` **不支持 focus**（传了报错），但 **`/codex:adversarial-review` 支持** flags 后跟自由文字（注入 prompt 的 `USER_FOCUS`）。

**落地**：新增 Step 0「已定设计前提清单」，每轮 review 用 `/codex:adversarial-review --wait --scope working-tree <前提清单>` 把已定决策传给 codex；收敛判据加例外「codex 质疑已定前提≠未收敛」；追加前提须先经人类确认，不自行否决 reviewer。

## 第 13 轮：带 focus 的 adversarial-review（验证新机制）

**机制成功**：codex **不再提文件集隔离**（接受了前提），转而用 adversarial 视角找出 3 个**前提之外、更深的设计缺陷**（前 12 轮都没发现）：

| 级别   | 问题                                                                                                                                | 修复                                                                                            |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| high   | Step 2 把「配置微调」判为琐碎跳过 → CI 权限/部署/认证/依赖版本等**高风险配置会绕过 review**（最需门禁的反而跳过）                   | Step 2 收窄：只跳纯文档/注释/格式；**配置变更绝不自动跳过**（除非论证不影响行为与安全）         |

## 关键转折 2：人类叫停「过度设计」，极简重写

跑到第 15 轮，人类指出两点，把 skill 从层层补丁堆叠中拉回：

1. **降级过度设计**：codex 前面 6~7 轮反复揪「没装 plugin / CLI 缺失 / token 失效怎么降级」——这些是边缘场景。人类：**假设本机 codex 装好，探测只判「codex 在不在」**，砍掉 5A/5B、意外 vs 结构性、非交互探测那一整套。
2. **staged/untracked 是自找麻烦**：`/commit` 前工作树没有谁提前分批 `git add`，**根本不需要区分 / 合并 staged/unstaged/untracked**，review 整树一把梭即可。codex 那个「漏审 staged」的 P1 建立在「用户提前手动 add」的不适用前提上。

**并让 codex 开全新线程（不带 15 轮历史、不带 focus）从零 review**——中立眼光只报 1 个 P1（还是那个不适用的 staged/untracked），印证「降级/staged 都是过度设计」。

**动作**：`/review-loop` 从 ~150 行**极简重写到 ~95 行**——保留全部核心（自主收口、整树 review+gitignore、loop+3 轮上限、传已定前提、配置不跳过、修复后重跑测试、`--` 隔离 focus），砍掉全部环境探测/降级累赘。宪法/README/commit 的降级二分同步简化为「codex 在→review，不在→告知后自审」。

**元经验（比「codex 逐层抓 bug」更深）**：

- 独立模型会**在一个不适用/错误的前提上锲而不舍地帮你「修」**，越修越复杂——人类质疑「这件事本身该不该做」的价值，是独立模型给不了的。
- **传已定前提 + adversarial-review** 能让 codex 火力聚焦到「前提之外」，挖出设计级缺陷（终止条件、配置跳过风险、focus 注入）。
- **定期开全新线程从零 review**，能戳破「层层补丁把简单问题搞复杂」——中立眼光是一味解药。

## 极简重写后的复审（从零 + 带 focus）

极简版又跑了几轮，抓出 3 个真问题——**都不是「过度设计」，而是极简时「砍过头」漏掉的核心**：

| 级别     | 问题                                                                                                                                                                                                                             | 修复                                                                                                                                                          |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P2       | 琐碎跳过含「纯文档文字」，但 `skills/*.md`、`GLOBAL_AGENTS.md` 这类**指令 / 规则文件**虽是 Markdown、却是**门禁与流程本身**，跳过等于让门禁「改自身规则时失效」（本轮改的正是它们！）                                            | Step 2 收窄：只跳真正的用户文档（`docs/`）；指令 / 配置文件明确排除、绝不跳                                                                                   |
| P2       | 极简的「只判 codex 在不在」，遇到「codex 装了但未登录」会判为可用、进 Step 4 后命令失败卡死                                                                                                                                      | Step 3「乐观试跑 + 失败降级」：不预检登录，但 review 命令**实际失败**就转降级、不卡死                                                                         |
| **high** | **极简砍过头的核心漏洞**：只判「codex 在不在」，漏了「**谁在写代码**」。skill 双端共享——**Codex 自己执行 `/commit` 时用 codex 审 codex，是同模型自审、却被标成「已过独立 review」**，摧毁了整个 skill 的立身之本（独立第二模型） | Step 3 补「独立 = 审的模型 ≠ 写的模型」判定：CC 执行 + codex 可用→独立✓；**Codex 执行→codex 非独立→一律降级本会话自审**。四处（skill/宪法/README/commit）同步 |

**这轮 high 是本轮最深的正确性发现**：它戳中「独立」到底指什么——不是「有没有 codex」，而是「审的模型 ≠ 写的模型」。极简化砍掉「两端不对称」的复杂表述时，把这个**核心正确性**也一起砍了；codex 从零 review 一眼揪回。修复后概念反而更本质、更简洁。**印证：简化要砍「累赘」，但不能砍「核心不变量」——区分二者，仍需独立 review + 人类共同把关。**

---

**自举结论**：本轮「用 review-loop review 自身实现」跑了约 15 轮，独立模型（codex）逐层抓出 CC 自审绝对想不到的真问题——范围漏审、lint 时序绕过、双轨契约不一致、降级路由到不存在入口、降级打断自主流程、focus 注入、配置跳过风险、无终止上限…**且每修一轮常连锁牵出下游**，正说明「必须是 loop 而非单次」。更重要的是，人类两次关键干预（推翻「文件集隔离」、叫停「降级过度设计」）证明：**独立模型 review 抓 bug 极强，但「前提对不对、是否过度设计」仍需人类把关**——二者结合才是 issue #24 想要的完整闭环。这段自举经历本身就是这套机制价值最有力的实证。
