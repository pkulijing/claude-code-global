## `skills/design/SKILL.md` 设计

### 参数

| 形态 | 行为 |
| --- | --- |
| `/design <背景描述>` | 新开一份讨论 |
| `/design --resume <主题>` | 续一份已有讨论（主题可模糊匹配 `docs/design/` 下的目录名） |
| 无参数 | 列出 `docs/design/*` 及各自状态，问用户是新开还是续哪份 |

### 开场

1. 不建 worktree、不进 plan mode（plan mode 退出即进入执行，与本形态语义冲突），在当前分支进行。
2. 从背景描述提炼中文主题 → `docs/design/<主题>/`。**目录已存在** → 停下问用户是续这份还是换个主题名，不覆盖。
3. 立即落 `DISCUSSION.md` 的阶段 0（用户原始背景**原样保留**）与 `DESIGN.md` 骨架（状态 `讨论中`），再开始第一轮提问。

### 讨论方法

- **阶段推进**：问题定义 → 约束与前提 → 方案空间 → 取舍 → 收敛成方案。这是默认路线而非死流程，可跳、可回退；每个阶段结束时向用户确认一次再往下走。
- **每轮只抛 1–2 个关键问题，每个都附 Agent 的建议与理由**，不做开放式盘问。
- 分清**事实**与**判断**：能读代码 / 查资料确认的自己去查（只读），查不到或属于「只有人知道」的问人；引用外部权威材料遵循宪法「先取原文」。
- 讨论期间**只写 `docs/design/<主题>/` 下的两份文件**，不改任何代码或其他文档。

### `DISCUSSION.md`：历史，只追加

```markdown
# <主题> · 讨论记录

## 阶段 0：背景输入（YYYY-MM-DD）
<用户原话，原样保留>

## 阶段 1：<议题>（YYYY-MM-DD）
- **输入**：用户提供的信息 / 约束
- **分析**：Agent 的观点与判断（附依据）
- **决策**：用户拍板了什么（关键处引用原话）
- **否决**：被放弃的选项及理由
```

- **写入时机**：用户每做一个关键决策、或一个阶段收束时**立即追加**，不等收尾 —— 防上下文压缩丢失，也是 `--resume` 的依据。
- **整理而非逐字**：不贴对话原文（阶段 0 除外）。
- **用户推翻先前决策属于决策**，要记（「推翻阶段 2 的 X，因为……」）；与宪法「自己写错自己改不留痕」不冲突 —— 那条管 Agent 自己的笔误，这里记的是用户的方向变化。

### `DESIGN.md`：快照，始终反映当前共识

```markdown
# <主题>

> 状态：讨论中 | 已定稿 | 已搁置
> 创建：YYYY-MM-DD · 更新：YYYY-MM-DD

## 目标与非目标
## 核心判断
## 方案框架
## 分阶段路线（可选）
## 开放问题
```

- 章节是建议骨架，按主题增删；**不要求落到可执行粒度**。
- 随讨论**整体改写**以反映当前共识，不追加历史（历史在 DISCUSSION）。
- `已搁置` 时在顶部补一行搁置原因。

### 续聊（`--resume`）

读两份文件 → 向用户复述「当前共识 + 开放问题 + 上次停在哪」→ 从开放问题继续。已定稿的方案被重开时状态改回 `讨论中`。

### 存档与收尾

- **会话中途存档**：一次会话结束但讨论未完时，`/commit` 一次（状态保持 `讨论中`），让跨设备续聊拿得到。
- **定稿**：用户确认方案 → 状态改 `已定稿`、更新日期、`DESIGN.md` 与 DISCUSSION 最后一个阶段对齐 → `/commit`。
- **搁置**：状态改 `已搁置` + 原因 → `/commit`。
- **明确不做**：不拆 issue、不碰 `DEVTREE.md`、不写 `SUMMARY.md`、不开 worktree。
- 与开发轮次的关系：以后 round 的 `PROMPT.md` / `PLAN.md` 引用 `docs/design/<主题>/DESIGN.md`，design 不反向维护。

## 关于 `/review-loop`

`docs/design/` 下的提交是纯用户文档，按 `/review-loop` 既有规则自动跳过。本轮自身改动含 `skills/*.md` 与 `GLOBAL_AGENTS.md`，属于「绝不自动跳过」的指令规则文件，照常走 review。
