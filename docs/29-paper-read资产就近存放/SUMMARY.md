# SUMMARY

## 开发项背景

`paper-read` skill 是「读一篇 paper 生成结构化中文笔记」的通用 skill。其 `SKILL.md` 在「文件格式 → 格式要求」一节硬性规定图片资产**保存到根目录下的 assets 文件夹**。

这是一处 BUG（措辞缺陷）：在按目录组织的笔记仓库（典型 paper-reading 仓库：按领域分文件夹、每篇论文独占子文件夹）里，「固定根目录 assets」的默认是错的，会带来三个问题：

- **就近性丢失**：图片离引用它的笔记很远，读/维护来回跳；
- **可移植性差**：一篇论文的笔记 + 图片无法作为自包含文件夹整体迁移/删除，根 assets 沉淀跨论文孤儿图片；
- **命名冲突**：多篇论文图片挤在同一根 assets，得靠前缀人为去重。

来自 [#15](https://github.com/pkulijing/claude-code-global/issues/15)。原先只能靠项目级 `CLAUDE.md` 覆盖这条默认，相当于把一个本该合理的默认推给每个项目兜底。

## 实现方案

### 关键设计

把默认从「固定根目录」改为**就近原则**：资产放在与笔记 markdown 文件同级的 `assets/` 目录。这样两种笔记形态默认都成立——

- 单文件笔记：`assets/` 就在笔记旁；
- 多层结构化仓库：`assets/` 落在论文文件夹内。

并显式给出相对路径引用 `![](assets/xxx.png)`，消除「根目录绝对位置」的歧义。

### 开发内容概括

单文件、单行措辞改写，无代码逻辑变动：

[skills/paper-read/SKILL.md:27](skills/paper-read/SKILL.md#L27)

- 改前：`论文内容中的重要插图、复杂的函数图像直接在markdown中插入，图片文件保存到根目录下的assets文件夹。`
- 改后：`论文内容中的重要插图、复杂的函数图像直接在 markdown 中插入；图片文件保存到与笔记 markdown 同级的 assets/ 文件夹（就近原则，而非固定根目录），引用使用相对路径 ![](assets/xxx.png)。`

### 额外产物

无（纯文档措辞改动）。skill 目录是目录级软链到两端 `skills/`，改内容即时生效，无需 `install.sh`。

## 局限性

- 改的是 skill 的「指引措辞」，靠 Coding Agent 在执行时遵循。已有的、按旧默认（根 assets）产出的存量笔记不会被自动迁移——但本轮目标只是修正默认，不涉及存量迁移，符合预期。
