# LLM 应用开发规则

接 LLM（function calling / tool schema / 让模型做多步任务）时读本文。**Python 侧的通用测试与工程规则见 `playbooks/python.md`，此处只写 LLM 特有的部分。**

## 1. 先选形态：「多步 Agent」还是「一次性任务拆分」

**接 LLM 之前先想清楚这一件事，它决定了返回结构长什么样。两者形态完全不同，混用会静默漏步。**

| | 多步 Agent | 一次性任务拆分 |
| --- | --- | --- |
| 有没有第二轮对话 | **有**：模型返回 tool_call → 系统执行 → 结果**回传**给模型 → 模型据此决定下一步 | **没有**：系统不回传任何执行结果 |
| 「一次只返回第一个 tool_call 然后等」 | **正确行为**，不是缺陷 | **致命**：模型在等一个永远不会来的结果 |
| 该用的返回结构 | 多个 tool_call，逐个执行回传 | **单个 tool + `steps` 数组**，「一次列全」成为参数的语义要求 |

**错配的形态是：系统不回传结果，却仍要求模型「返回 tool_call」。** 那个动作形态正是 agent loop 的第一拍，模型会按训练先验只返回第一步然后等——而它永远等不到。

> 「回传」的具体形态**随 provider 而异，别照字面抄**：OpenAI Chat Completions（及 deepseek / qwen 等兼容协议）用 `role: "tool"` 消息；Anthropic Messages API 没有 `role:tool`，用的是 `role: "user"` 里的 `tool_result` content block。本节讲的是**形态选择**，与具体协议无关。

### 为什么这个坑值得单开一节：症状极具迷惑性

- **有依赖的请求才翻车，无依赖的照常成功**。真实案例：「建 GitLab 账号 + 加入两个组」（后两步依赖第一步）只执行了建号；而「同时加入两个组」（彼此无依赖）100% 正常。
- 表现为「时好时坏、冷不丁坏一次」，**漏掉的那一步不留任何痕迹**——确认卡片正常渲染、执行成功、日志记 info。**人只能看见清单上有什么，看不见缺什么。**

### 实测：这是模型的稳定策略，不是采样噪声

每格 20 次，复用生产 prompt 与 schema：

| 形态 | deepseek-v4-flash | qwen3.7-max |
| --- | --- | --- |
| 多 tool_call（错配） | 5% | 75% |
| 单 tool + `steps` 清单 | **95%** | **100%** |

两条推论，都是实测出来的：

- **调参救不了**：在错配形态下调 `parallel_tool_calls=True` / `temperature=0`（各单开、再双开），三种配置的符合率始终贴地 —— 5% / 5% / 0%。（源数据未标注这三个值属哪个模型；数值与表中 deepseek 的 5% 错配基线一致，应为 deepseek。）
  ⚠️ 这组数据只够证明「调参没把错配救回来」，**不足以证明这两个参数本身无效** —— `parallel_tool_calls` 在 OpenAI 兼容 API 上**默认就是 true**，显式设 true 等于什么都没改。真要归因到参数，得先确认它改变了默认行为。
- **只改 prompt 措辞而不改返回结构，救不回来**：把角色重设为「任务拆解器」但仍走多 tool 通道 → deepseek 5% → 15%、qwen 75% → 35%，两个模型都**远达不到**换结构后的 95% / 100%，且过半数直接退化成纯文本回复。**角色描述与返回结构必须一致**，否则模型在「拆解」与「调用」之间摇摆。
  > 源数据把这一格记作「两个模型都大幅退化」，但按同表的错配基线（5% / 75%）核对，deepseek 实为小幅上升、只有 qwen 退化。**结论「改措辞不能替代改结构」不受影响**，此处按数字如实记；要引用「退化」这个说法请先回源核对。

## 2. LLM 组件的单测必须是统计性的，且不能用 fake 替模型作答

**判据：凡是「模型会不会这么做」的断言，跑一次 assert 通过不提供任何保障。** 必须跑 N 次看符合率，并把用例固化成可重复的基准脚本。

反面样本来自上一节那个项目：改造前的复合请求单测**全绿**——它用 fake 直接构造了两个 `tool_calls`，测的是「给了多个我收不收得全」，恰好绕开「模型给不给」这个唯一的真问题。

> 与 `playbooks/python.md` §4「声明式 schema + 自然语言 prompt 双写处必须加结构性防漂移测试」同族：那条管 schema 与 prompt 之间的漂移，这条管「模型行为」这个断言对象本身。两条都指向同一个失败模式——**用 fake 替模型作答的单测，测的是自己的假设，不是模型**。
